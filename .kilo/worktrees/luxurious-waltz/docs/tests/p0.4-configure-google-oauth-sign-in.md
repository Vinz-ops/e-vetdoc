# [P0.4] Configure Google OAuth sign-in

## Why This Task Mattered

Google sign-in gives E-VetDoc users a familiar way to access the app while keeping OAuth credentials in Google Cloud and Supabase rather than in application code.

## What Was Verified

- OAuth callback implementation: pass — the app sends the user to `/auth/callback?next=/dashboard` and exchanges the returned code for a session.
- Supabase Google provider: pass — Google sign-in was enabled with the configured OAuth client.
- Automated lint: not completed — the workspace currently blocks ignored dependency build scripts before lint can run.

## Human Evidence

The project owner configured the Google Cloud OAuth client, added an allowed test user, enabled the Supabase Google provider, and confirmed in the browser that **Continue with Google** reached `/dashboard`. Screenshots showed the Google provider enabled with the secret masked; no credentials were stored in the repository.

## Result

Pass. The configured Google test user can sign in through Supabase and reach the E-VetDoc dashboard.
