# [P1.2] Implement profiles, role policies, and guarded routes

## Why This Task Mattered

Role-aware access prevents an account from viewing administrator-only screens or granting itself access to another pet. This task adds server-side route checks and database rules so the dashboard follows each user’s role.

## What Was Verified

- `next build`: pass.
- Route access: pass — signed-out users are sent to login with a return path; owners and veterinarians are sent away from Team; administrators see Team Management and its Admin Only badge.
- Dashboard navigation: pass — Owners is hidden from owners, available to veterinarians and administrators, and Settings is visible to every role.
- RLS: pass — the retired `owners insert pet_owners` policy was removed; an owner could not self-link to an unrelated pet or change their role, while a permitted `full_name` update succeeded.

## Human Evidence

The verification was performed in the production app and Supabase SQL Editor. Screenshots showed the expected Team and role-specific dashboard states; temporary SQL checks used transactions and rollbacks, so no test data remained.

## Result

Pass. The protected Team route and the profile and pet-ownership authorization boundaries behaved as required.
